# Console 串口自动化配置下发工具

通过 Console 串口直连网络设备，通过读取表格实现自动化配置下发。自动计算配置与监听接口拔插。

无适用场景，代码仅供参考，本版本不明示或暗示可用场景。

---

## 软件架构

本脚本采用 **三层架构** 设计，职责清晰，便于理解和修改。

### 整体流程

```
┌─────────────────────────────────────────────────────────────┐
│                    主循环（匹配模式）                        │
│                                                             │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐             │
│   │ ① 监听   │──► │ ② 匹配   │──► │ ③ 下发   │             │
│   │ 设备连接  │    │ Excel    │    │ 配置     │             │
│   └──────────┘    └──────────┘    └──────────┘             │
│        ▲                                       │            │
│        │         ┌──────────┐                  │            │
│        └─────────│ ④ 等待   │◄─────────────────┘            │
│                  │ 断开     │                               │
│                  └──────────┘                               │
└─────────────────────────────────────────────────────────────┘
```

### 三层架构详解

```
┌─────────────────────────────────────────────────────────────┐
│                    输入层 (input_layer)                      │
│  获取：Excel路径、工作模式、起始行号、配置确认开关           │
│  输出：(excel_path, mode, start_row, print_config_flag)     │
├─────────────────────────────────────────────────────────────┤
│                    计算层 (calculation_layer)                │
│  读取 Excel，逐行解析，为每台设备生成配置模板               │
│  核心函数：generate_templates(device_data) → templates      │
│  输出：device_configs（设备配置列表）                        │
├─────────────────────────────────────────────────────────────┤
│                    下发层                                    │
│                                                             │
│  ┌─ 匹配模式 ──────────────────────────────────────────┐   │
│  │  deploy_layer() → 主循环：                           │   │
│  │    wait_for_device()  监听 COM 口，检测设备提示符    │   │
│  │    match_device_in_excel()  按设备名匹配 Excel 行    │   │
│  │    check_status_col()  检查完成标记                  │   │
│  │    deploy_to_device()  执行配置下发                  │   │
│  │    write_status_col()  写入完成标记                  │   │
│  │    wait_for_disconnect()  等待拔线断开               │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─ 顺序模式 ──────────────────────────────────────────┐   │
│  │  deploy_layer_sequence() → 按行号顺序逐台下发：      │   │
│  │    流程与匹配模式相同，但跳过匹配步骤                 │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 各函数调用关系

```
input_layer()
    │
    ▼
calculation_layer()
    │  ├── generate_templates()    ← 修改此函数自定义配置命令
    │
    ▼
deploy_layer()  /  deploy_layer_sequence()
    │
    ├── wait_for_device()          ← 监听 COM 口，检测设备
    ├── match_device_in_excel()    ← 按设备名匹配 Excel
    ├── check_status_col()         ← 检查是否已下发过
    ├── deploy_to_device()         ← 执行配置下发
    │   └── execute_one_template() ← 执行单个模板
    │       ├── 发送配置命令
    │       └── 保存检测
    ├── write_status_col()         ← 写入完成标记
    ├── wait_for_disconnect()      ← 检测物理断开
    └── close_serial()             ← 关闭串口
```

### 关键函数说明

| 函数                        | 所属层 | 作用                                  |
| --------------------------- | ------ | ------------------------------------- |
| `input_layer()`           | 输入层 | 获取用户输入的 Excel 路径、模式等参数 |
| `calculation_layer()`     | 计算层 | 读取 Excel，生成设备属性              |
| `generate_templates()`    | 计算层 | 根据设备数据生成配置命令模板          |
| `deploy_layer()`          | 下发层 | 匹配模式主循环                        |
| `deploy_layer_sequence()` | 下发层 | 顺序模式主循环                        |
| `wait_for_device()`       | 下发层 | 打开 COM 口，发回车检测设备提示符     |
| `match_device_in_excel()` | 下发层 | 按设备名在 Excel 中查找匹配行         |
| `check_status_col()`      | 下发层 | 检查设备是否已完成下发                |
| `deploy_to_device()`      | 下发层 | 执行配置下发全流程                    |
| `execute_one_template()`  | 下发层 | 执行单个模板的所有命令 + 保存检测     |
| `write_status_col()`      | 下发层 | 下发完成后写入完成标记                |
| `wait_for_disconnect()`   | 下发层 | 检测 Console 线物理断开               |
| `close_serial()`          | 下发层 | 安全关闭串口                          |

## Excel 格式要求

Excel 文件**不能有合并单元格**，各列含义如下（可在代码中 `calculation_layer` 函数的配置定义区域修改列号）：

| 列       | 默认列 | 说明                    |
| -------- | ------ | ----------------------- |
| 设备名   | E 列   | 用于匹配设备的名称      |
| VLAN     | F 列   | 线缆 VLAN ID            |
| 完成标记 | G 列   | 下发完成后自动写入 TRUE |

> 第 1 行为表头，数据从第 2 行开始。
> 如需更多设备属性（如设备型号、位置等），可在代码中 `more_cols` 列表里扩展列号，然后在 `generate_templates` 函数中通过 `device_data` 字典使用这些值。

## 配置模板详解

所有设备的下发命令由 **`generate_templates(device_data)`** 函数生成。这个函数位于代码的"计算层"区域，你需要在这里定义每台设备要执行的命令。

### 函数位置

在 `console_deployer.py` 中搜索 `def generate_templates` 即可找到。

### 模板结构

```python
def generate_templates(device_data):
    # device_data 包含 Excel 中当前行的所有数据
    # 例如: device_data["cable_vlan"] 就是 F 列的 VLAN ID

    templates = [
        # 模板 1：第一个配置阶段
        [
            'sys',                                    # 命令1：进入系统视图
            f'vlan {vlan_id}',                        # 命令2：创建 VLAN（使用变量）
            'quit',                                   # 命令3：退出
            'save force',                             # 保存命令（倒数第二条）
            'The current configuration is saved...',  # 完成检测标记（最后一条）
        ],
        # 模板 2：第二个配置阶段
        [
            'sys',
            f'vlan {vlan_id+1}',
            'quit',
            'save force',
            'Validating file. Please wait...',
        ],
    ]
    return templates
```

### 模板规则

| 位置                     | 内容         | 说明                                                   |
| ------------------------ | ------------ | ------------------------------------------------------ |
| **前面的元素**     | 配置命令     | 按顺序逐条下发的配置命令                               |
| **倒数第二个元素** | 保存命令     | 如 `save force`，用于保存配置                        |
| **最后一个元素**   | 完成检测标记 | 保存成功后设备回显中包含的字符串，用于判断保存是否完成 |

> 每个模板代表一个独立的配置阶段。程序会按顺序执行所有模板，每个模板内的命令也按顺序执行。

### 使用 Excel 变量

`device_data` 字典包含了 Excel 当前行的所有数据，你可以在模板中用 `f-string` 引用：

```python
# Excel 中 F 列的值 → device_data["cable_vlan"]
f'vlan {device_data["cable_vlan"]}'

# 如果需要在 more_cols 中扩展了 G、H、I、J 列
# 则在 raw_data 中可以通过 device_data["more_data"][0] 等访问
```

### 自定义模板示例

```python
# 示例：为设备配置多个 VLAN 和接口
templates = [
    # 阶段1：创建 VLAN 100 并配置接口
    [
        'sys',
        'vlan 100',
        'port gigabitethernet 1/0/1',
        'port link-type trunk',
        'port trunk permit vlan 100',
        'quit',
        'save force',
        'The current configuration is saved to the active main board successfully',
    ],
    # 阶段2：创建 VLAN 200 并配置接口
    [
        'sys',
        'vlan 200',
        'port gigabitethernet 1/0/2',
        'port link-type access',
        'port access vlan 200',
        'quit',
        'save force',
        'The current configuration is saved to the active main board successfully',
    ],
    # 阶段3：配置管理地址
    [
        'sys',
        'interface vlan-interface 100',
        'ip address 192.168.1.1 255.255.255.0',
        'quit',
        'save force',
        'The current configuration is saved to the active main board successfully',
    ],
]
```

> **提示**：不同厂商设备的命令不同，请根据实际设备型号编写命令。保存命令和完成检测标记也需根据设备实际回显调整。

## 使用说明

### 1. 修改串口配置（如需）

打开 `console_deployer.py`，在顶部找到串口配置区域：

```python
COM_PORT = 'COM7'       # 修改为实际串口号
BAUDRATE = 9600         # 修改为实际波特率
```

### 2. 修改配置模板

找到 `generate_templates` 函数，根据你要下发的配置修改模板内容（参考上面的模板详解）。

### 3. 运行程序

```bash
python console_deployer.py
```

### 4. 按提示操作

```
① 拖入 Excel 文件到命令行窗口，按回车
② 选择工作模式：1=匹配模式 / 2=顺序模式
③ 顺序模式下输入数据起始行号
④ 选择是否下发前确认配置
```

### 5. 工作流程

**匹配模式（推荐）：**

```
① 程序监听 COM 口，等待设备连接
② 插上 Console 线 → 自动检测设备提示符 → 提取设备名
③ 在 Excel 中匹配设备名 → 找到对应配置 → 自动下发
④ 下发完成 → 在 Excel 写入完成标记 → 等待拔线
⑤ 拔线 → 自动检测断开 → 返回 ① 等待下一台设备
```

**顺序模式：**

```
① 按 Excel 行号顺序，提示你连接第 N 台设备
② 插线 → 自动检测 → 下发配置 → 写入标记 → 等待拔线
③ 拔线 → 自动检测断开 → 提示连接第 N+1 台设备
```

## 运行说明

### 控制台输出

程序运行过程中会输出以下信息：

| 输出前缀        | 含义                                                                  |
| --------------- | --------------------------------------------------------------------- |
| `[DEBUG]`     | 调试信息（仅 `PRINT_DEBUG=1` 时显示），包括串口收发数据、探测详情等 |
| `✅` / `❌` | 操作成功 / 失败                                                       |
| `⏳` / `🔍` | 等待中 / 正在检测                                                     |
| `📡`          | 配置下发中                                                            |
| `🔌`          | 串口连接 / 断开事件                                                   |
| `📝`          | Excel 写入操作                                                        |

### 脚本运行产生的文件

运行后会在脚本所在目录下创建 `log/` 文件夹，包含：

| 文件                                  | 内容                               |
| ------------------------------------- | ---------------------------------- |
| `log/ConsoleDeploy_{timestamp}.txt` | 详细执行日志（含时间戳）           |
| `log/Complete_{timestamp}.txt`      | 已下发完成的设备列表               |
| `log/Failed_{timestamp}.txt`        | 下发失败的设备及原因               |
| `log/{设备名}/{日期}/{时间}/`       | 配置备份文件（启用备份功能时产生） |

### 网络流量方向

```
┌─────────────────┐      Console 串口线       ┌──────────────┐
│  笔记本/PC       │ ◄──────────────────────► │  网络设备     │
│  (运行本工具)    │      TX ────► RX          │  (交换机/     │
│                  │      RX ◄──── TX          │   路由器等)   │
│  COM7 (例)       │                           │  Console 口   │
└─────────────────┘                           └──────────────┘
```

- **数据流向**：笔记本 → TX → 设备 RX（下发配置命令）；设备 → TX → 笔记本 RX（回显）
- **网络隔离**：Console 串口是带外管理口，配置下发期间不影响设备现有网络业务
- **无网络依赖**：整个过程不依赖 IP 网络，设备无需配置管理 IP 即可操作

## 完成标记机制

设备下发完成后，程序会：

1. **写入 Excel**：在完成标记列写入 `TRUE`，下次启动程序时可以识别该设备已完成
2. **加入内存缓存**：本次运行期间直接命中缓存，无需重新读取 Excel

当再次匹配到同一台设备时：

- 如果完成标记列已有 `TRUE`，程序会询问你：
  - 输入 `y`：重新下发配置（覆盖标记）
  - 输入 `n`：跳过下发，直接进入等待断开

## 调试开关

在代码顶部可调整以下开关：

| 开关                | 默认值 | 说明                                       |
| ------------------- | ------ | ------------------------------------------ |
| `PRINT_DEBUG`     | 1      | 1=打印详细串口通信日志，0=仅打印用户提示   |
| `SAVE_FLAG_DEBUG` | 0      | 1=正常保存检测，0=跳过保存检测直接等待断开 |

> 任一开关处于非生产状态时，程序启动会打印警告。

## 工作模式对比

| 模式               | 适用场景              | 优点                                                     | 缺点                        |
| ------------------ | --------------------- | -------------------------------------------------------- | --------------------------- |
| **匹配模式** | 设备连接顺序不确定    | 自动匹配，插错设备也能识别                               | 需要在 Excel 中有唯一设备名 |
| **顺序模式** | 设备按 Excel 顺序连接 | 无需设备名列，按行号定位，适用于网络开局等设备名相同情况 | 连接顺序必须与 Excel 一致   |

## 串口参数

| 参数     | 默认值  | 说明                     |
| -------- | ------- | ------------------------ |
| COM 口   | COM7    | 在代码顶部修改           |
| 波特率   | 9600    | 在代码顶部修改           |
| 连接超时 | 30 分钟 | 超过后重置计时，继续监听 |
